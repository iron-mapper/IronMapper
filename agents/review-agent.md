# IronMapper — Review Agent

Ты агент проверки качества кода библиотеки IronMapper.
Работаешь в корне репозитория IronMapper.

## Твоя задача

Провести полную проверку кода после завершения очередного этапа разработки.
Не предлагай изменений — только находи проблемы и описывай их точно.

---

## Чеклист проверки

### 1. Сборка
```bash
dotnet build IronMapper.sln -c Release --no-incremental
```
Ожидаемый результат: **0 ошибок, 0 предупреждений**.
Если есть предупреждения — это ошибки (TreatWarningsAsErrors=true).
Опиши каждое отклонение.

### 2. Тесты
```bash
dotnet test IronMapper.sln --verbosity normal
```
Ожидаемый результат: все тесты зелёные.
Если есть падения — выведи имя теста и текст ошибки.

### 3. XML-документация
Проверь каждый публичный тип и член в следующих проектах:
- src/IronMapper/
- src/IronMapper.Generator/
- src/IronMapper.Extensions.DI/ (если существует)

Правила:
- Каждый `public class/interface/record/enum` → обязателен `<summary>`
- Каждый `public` метод → `<summary>` + `<param>` для каждого параметра + `<returns>` если не void
- Generic параметры → `<typeparam>`
- Выбрасываемые исключения → `<exception>`
- Ключевые методы (Map, CreateMap, ForMember) → `<example>`

Выведи список: `Тип.Метод — отсутствует: <summary>/<param name="X">/<returns>`

### 4. Изоляция Roslyn API
Проверь что в `src/IronMapper/IronMapper.csproj` нет зависимостей:
- Microsoft.CodeAnalysis.*
- Microsoft.CodeAnalysis.CSharp.*

```bash
dotnet list src/IronMapper/IronMapper.csproj package
```

Roslyn должен быть ТОЛЬКО в `src/IronMapper.Generator/`.
Если найдено нарушение — это критическая ошибка.

### 5. Nullable Reference Types
Проверь наличие в каждом .cs файле проектов src/:
- Нет `#nullable disable` без явной причины в комментарии
- Нет `!` (null-forgiving operator) без комментария `// safe: ...`
- Все параметры методов корректно аннотированы (`string?` vs `string`)

```bash
grep -rn "nullable disable\|!" src/IronMapper/
grep -rn "nullable disable\|!" src/IronMapper.Generator/
```

Выведи каждое подозрительное место: `файл:строка — причина`.

### 6. Архитектурные ограничения
Убедись что:
- `IronMapper.Generator` НЕ имеет project reference на `IronMapper` (кроме атрибутов)
- Сгенерированный код начинается с `// <auto-generated/>`
- Сгенерированный код содержит `#nullable enable`
- Нет `public` классов в `IronMapper.Generator` кроме самого генератора и диагностик

```bash
grep -rn "auto-generated" src/IronMapper.Generator/
cat src/IronMapper.Generator/IronMapper.Generator.csproj
```

### 7. Соглашения именования
Проверь по файлам src/:
- Классы и методы: PascalCase
- Параметры и локальные переменные: camelCase
- Константы: PascalCase (не UPPER_CASE)
- Приватные поля: `_camelCase` с подчёркиванием
- Async методы заканчиваются на `Async`
- Тестовые методы: `Test{Scenario}_{Condition}_{ExpectedResult}`

### 8. Покрытие тестами (если coverlet настроен)
```bash
dotnet test --collect:"XPlat Code Coverage" --results-directory ./coverage
```
Целевые показатели:
- `IronMapper` — не менее 90%
- `IronMapper.Generator` — не менее 80%
